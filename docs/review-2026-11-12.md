## 03. Blockers

### B1. glTF attribute accessors do not agree in count, so every mesh is invalid ✓

`python/webexport/writers/gltf.py:471-475`, `:310-317`; `tests/test_webexport_gltf.py:147-155`

`POSITION` is written per point; `NORMAL` and `TEXCOORD_0` are written per triangle corner; the index buffer indexes the point arrays. glTF requires all vertex attributes of a primitive to be parallel and indexed together, and `validate_glb` never compares counts.

I confirmed this against the committed fixture:

```
floor       POSITION 4   NORMAL 6   TEXCOORD_0 6   indices 6
pedestal_l  POSITION 8   NORMAL 36                 indices 36
```

**Failure:** normals are addressed by indices that point into a shorter array, so faces shade with the wrong normals; a UV seam cannot be represented at all; strict validators reject the file.
**Fix:** duplicate vertices per corner, build indices over that array, write all attributes from it, and add an attribute-count check to `validate_glb` and to the M7 test.

### B2. Both writers skip geometry inside USD instances, and the report still says GO

`writers/gltf.py:429,434,438`; `writers/x3d.py:264,381,444,468`

`stage.Traverse()` does not visit instance proxies. `inventory.gather` deliberately does (`Usd.PrimRange.Stage(..., Usd.TraverseInstanceProxies())`), so the report counts meshes the writers never see.

**Evidence from the lane:** a stage with two instanceable references gives `traverse meshes: []`, `inventory meshes: 2`, `glb meshes: 0`, verdict `GO, WITH NOTES`; X3D raises `the Scene is empty`. It survives `FlattenLayerStack` too, so the HDA path is affected.
**Failure:** any Solaris shot instanced with instanceable references exports an empty glb, or an exception, with a green-ish report.
**Fix:** use `Usd.PrimRange.Stage(stage, Usd.TraverseInstanceProxies())` for meshes, cameras, lights and instancers.

### B3. UVs use the wrong index space in glTF, and X3D writes no texture coordinates

`writers/gltf.py:295-307`, `:473-475`; `writers/x3d.py:234-243`

`_uvs` treats point indices as UV indices and drops any index above the point count. X3D emits no `TextureCoordinate` at all, so its `ImageTexture` relies on default box mapping.

**Evidence:** a quad with `st` indices `[4,5,6,7]` exports `[[0.0,0.0]] * 6`.
**Failure:** textured assets get wrong or missing texture placement in both formats, with no report line.
**Fix:** per-corner UVs together with the vertex expansion from B1; X3D writes `TextureCoordinate` and `texCoordIndex`.

### B4. The glTF player ignores the exported camera and renders from the origin ✓

`viewer/players/gltf.html:92`

The framing block is guarded by `if (report.cameras === 0)`. Every export carries a camera, so the guard is false, the player camera stays at `(0,0,0)` looking down `-Z`, and the authored camera is never used. I confirmed the guard and that `shots/187/08-gltf-player.png` exists and is 13 KB, consistent with a near-blank frame.

**Failure:** every glTF export opens unusable, and the repo ships that screenshot as a product shot.
**Fix:** if a camera node exists, decompose its world matrix into the player camera and apply the same portrait widening as `main.js`; frame from bounds only when no camera exists.

## 05. Minors

- **Card drift** (`docs/web-export.md:71,96,108`): says each finding names up to three examples, but the renderer prints one; exit codes 5, 6 and 7 are undocumented; "Proven" lists only the USD folder.
- **`release.py` gate** (`tools/release.py:45-49`): accepts any successful push workflow, not specifically `CI`, and `checks()` has no unit test. The tag target and the notes parser are sound.
- **Shadows** (`viewer/main.js:269`): the shadow camera is never fitted, and every non-distant light becomes a point light, so a set larger than the default bounds loses shadows silently.
- **`poleAxis` untested** (`tests/browser/smoke.mjs:33-50`): the fixture is Y-up with no pole axis, so the Z-up and `"Z"` branches of the dome orientation are unverified.
- **Two smoke assertions cannot fail** (`smoke.mjs:137,152`): `lastVariantSwitch.option` is written by the code under test, and `applied.showHud === undefined` is structurally guaranteed. Two checks also rely on fixed sleeps.
- **Player reporting understates** (`players/gltf.html:79-86`, `players/x3d.html:47-64`): instanced triangles are counted once; X3D counts only two light types and `PhysicalMaterial`; its failure path leaves the page looking hung.
- **Concave n-gons** (`writers/gltf.py:194-201`, `writers/x3d.py:90-97`): fan triangulation fills the notch with a triangle outside the face.
- **X3D texture name collisions** (`writers/x3d.py:227-232`): two `wood.png` files from different folders overwrite each other, and `bytes` double-counts.
- **Empty scene raises** (`writers/x3d.py:279-281`): it aborts sibling formats after the glb is already written.
- **Partial output** (`writers/usd_folder.py:309-323`, `writers/usdz.py:109-115`): no rollback mid-copy; the old `.usdz` is unlinked before the repack, so a failure loses the last good archive.
- **Hidden prims and alpha** (`writers/gltf.py:429-431`, `:108`): invisible meshes export visible; `inputs:opacity` is dropped.
- **Viewer details** (`viewer/main.js:318-326,280,426`): `jsLoaded` is set before the load so a failed USDLoader fetch cannot retry; the USD camera is resolved once and can go stale; `inventory` is computed before purposes are applied.

## 06. What held up

Worth stating explicitly, because a review that only lists defects misleads.

- **The USD folder and USDZ paths are clean.** Plan, path rewriting, staging cleanup, `/WebSettings` on the copy, and both validators held up under inspection and tests.
- **The dome orientation maths is correct**, including the pole-Z branch; the latlong convention matches the installed UsdLux schema, and the measured `[0, -15, 0]` agrees with a 75° dome.
- **Light intensity conversion matches UsdLux**: radiance, exposure, area factor unless `normalize`, distant solid angle, `decay = 2`.
- **Camera framing is correct**: delegate fov is vertical, portrait widening works, and the phone screenshot shows it.
- **COOP/COEP are right on every response**, and the CDN sends a cross-origin resource policy that satisfies COEP.
- **Release safety is sound**: the notes parser takes only the exact version section, refuses an empty one, and the tag targets the verified commit; the claims test guards version, formats, links and changelog shape.
- **The decisions log matches the code**, and all four formats are exercised by the unit suite.

## 07. Refinements, in priority order

1. **One hostile fixture and one conformance gate.** A stage combining a UV seam, a Z-up centimetre setup, an instanceable reference, a scaled and oriented PointInstancer and two variant sets, exported in CI and checked by the Khronos glTF validator or a strengthened `validate_glb`. It would have caught B1, B2, B3, M4, M6 and M7 before release.
2. **Writers report what they wrote.** `inventory` already counts meshes, cameras, lights and instancers; have each writer return its own counts and let `api.export` add a `changes` item for every gap. Silent data loss becomes a report line.
3. **Give the browser tests something real to assert.** Expose the camera state, the selected variant per set and the environment key in `__report`, then replace the dead assertions and the fixed sleeps.
4. **Normalise axis and units once**, in a root node, and say so in the report.
5. **Make the helper gates gate, or call them advisory.** The router's agreement check exits 0 on disagreement, `decide.py` never escalates on a failed check, the census assumes `ND_*` when Jev is off, and the release gate accepts any push workflow.
6. **Keep the committed fixtures honest.** Regenerate them in CI or compare a structural digest, and make the expected mesh count exact.

## 08. What this means for the harness

The findings share a shape: **the system reports a state it has not verified.** A validator that does not compare counts, a schema test that skips, a census that assumes, a batch test that asserts nothing, a player that ignores its own camera, a note that says "every timecode" while sampling every second one.

A development harness built for this repo should therefore be judged on one thing above all: whether it can turn "we checked" into "the check ran and could have failed". That is the subject of `plan/harness-blueprint.md` and its spec.
